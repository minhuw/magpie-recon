# 储备

magpie 窗口里的一页。不改 magpie 本身。只读两个文件：

- `usage.jsonl`：每次调用的时间、token、网关钥匙、订阅账号
- `quota-history.json`：每个账号每个窗口的剩余百分比、窗口起点、reset

额度历史是 JSON，不是 JSONL。magpie 写在配置目录里，和 `usage.jsonl` 放在一起（默认 `~/.config/magpie`，或 `$XDG_CONFIG_HOME/magpie`）。

## 安装

在要看的那台 magpie 上：

```sh
magpie plugin add github:minhuw/magpie-recon
```

在插件页打开它，侧边栏会出现「储备」。第一次打开会稍等，页面要等本机服务起来再跳过去。

配置目录不在默认位置时，插件行的 Options 写成：

```json
{ "port": 3478, "dir": "/你的/magpie配置目录" }
```

`dir` 要是绝对路径。空字符串表示用默认目录。环境变量 `MAGPIE_RESERVE_DIR` 同样是这个目录。

## 这一页上有什么

- 一句话：偏快（会在 reset 前用完）、偏慢（可以加速）、有账号几乎没花（可以少登），或和均匀消耗差不多。
- 总剩余、最近几小时的消耗速度、按斜率预计的见底时间、下一次 reset。
- 30 天的 K 线。每个账号取最长的窗口，画剩余百分比的平均。阳线多半是 reset，阴线是在消耗，底下的柱是当天 token。
- 每个还开着的窗口：剩余、均匀消耗下应剩多少、reset、偏快还是偏慢。
- 网关钥匙和订阅账号各自的 24 小时、3 天、7 天、30 天用量，以及 30 天趋势。

快慢看的是厂商读数相对均匀消耗的位置，再加上最近 6 小时的斜率。一个账号有多个窗口时，用最紧的那个下判断。剩余 token 是用这个周期里账本记到的调用、按已用百分比反推的；用得太少就不推，避免把一点点调用放大成整个窗口。

## 它做不到的

- 分不清「把已经有的号再登上来」和「去新买号」。暂停的号、没写进这两个文件的号，这里看不到。偏快时只能说：减速，或者再补账号。短窗口（6 小时内就 reset）会说明不必为此补号。
- 「人」是网关钥匙的名字。大家共用一把钥匙时，账本分不出人。
- 不读 `providers.json`，所以看不到 API key，也不知道哪些号被暂停了。
- 模型池和账号级窗口分不开：反推剩余时，用的是这个账号的全部调用。

服务只听 `127.0.0.1`，并且核对 Host。页面跑在 magpie 的沙箱里，自己不能发请求，只能把框架导航到这个服务。
