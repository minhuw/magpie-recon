# 储备

magpie 窗口里的一页。不改 magpie 本身。只读两个文件：

- `usage.jsonl`：每次调用的时间、token、网关钥匙、订阅账号
- `quota-history.json`：每个账号每个窗口的剩余百分比、窗口起点、reset

额度历史是 JSON，不是 JSONL。magpie 写在配置目录里，和 `usage.jsonl` 放在一起（默认 `~/.config/magpie`，或 `$XDG_CONFIG_HOME/magpie`）。

## 安装

在要看的那台 magpie 上：

```sh
magpie plugin add github:minhuw/magpie-recon
```

在插件页打开它，侧边栏会出现「储备」。第一次打开会稍等，页面要等本机服务起来再跳过去。

配置目录不在默认位置时，插件行的 Options 写成：

```json
{ "port": 3478, "dir": "/你的/magpie配置目录" }
```

`dir` 要是绝对路径。空字符串表示用默认目录。环境变量 `MAGPIE_RESERVE_DIR` 同样是这个目录。

## 页面

主图按 Codex、Claude 分开显示前 15 天的实际剩余和后 15 天的预测，只使用每个账号的周额度窗口。约 7 天的窗口会被识别为周额度；5 小时等短窗口不参与预测。每个供应商取这些周窗口的平均剩余百分比；各账号按最近 3 天的平均每日额度下降速度分别外推、在零处截断，再合并成曲线。预计耗尽时间显示在图上方。

历史不足 3 天时，按可比较读数间的实际观测时长折算每日消耗，不把缺失的历史当作零消耗。跨重置且无法比较的读数区间不计入消耗或观测时长。

跨重置的预测明确假设周额度恢复到 100%，之后仍按相同的 3 天平均速度消耗。重置圆点直接标在曲线上，悬停可查看对应账号。

- 所有周额度都在任何重置前耗尽：显示「会耗尽」和时间。
- 只有部分账号会耗尽：整体仍显示「不会耗尽」；重置圆点可查看具体账号。
- 先遇到重置：估算重置前还剩多少。
- 读数不足时不预测；至少需要两个时间不同、属于同一重置周期的读数。最近 3 天没有净消耗时显示不会耗尽。

展开的「账号窗口」表格可检查单个账号的剩余、耗尽预测和 reset。

第二行是 30 天每日用量。柱高使用「账号当量」：每个账号取最长窗口，把当天剩余百分比的下降相加，再除以 100。例如账号 A 下降 30%、账号 B 下降 20%，当天合计 0.50 账号当量。reset 造成的回升不算消耗；当天缺少任一账号的读数时，账号当量显示未知。

默认选中今天。点击、触摸或用键盘选择其他日期，可查看当天的 token 和账本记录的 API 等价成本。token 和成本保持原始单位，不按订阅价格换算；账本不完整或成本缺失时会明确标出。

服务只听 `127.0.0.1`，并且核对 Host。页面跑在 magpie 的沙箱里，自己不能发请求，只能把框架导航到这个服务。
